# data/

腸活アプリの食物繊維データ層。出典：**日本食品標準成分表（八訂）増補2023年（文部科学省）**
※ アプリ内にも同じ出典表示が必要（利用条件）。値は全て**可食部100gあたり(g)**。

---

## fiber_foods.csv — 食品マスタ（2,538食品）

| 列 | 内容 |
|---|---|
| `code` | 食品番号（5桁） |
| `name` | 成分表の正式名称 |
| `fiber_total` | **食物繊維総量（第2章本表の値。実装で使うのはこれ）** |
| `kcal` | エネルギー(kcal/100g) |
| `soluble_prosky` / `insoluble_prosky` / `total_prosky` | プロスキー変法（水溶性/不溶性/総量） |
| `sol_low_aoac` / `sol_high_aoac` / `insol_aoac` / `total_aoac` | AOAC2011.25法（低分子量水溶性/高分子量水溶性/不溶性/総量） |
| `resistant_starch` | 難消化性でん粉 |
| `method` | `prosky`(1,263) / `aoac2011.25`(104) / `both`(79) / `none`(1,092) |

`Tr`(微量)は0.0、未測定は空欄に正規化済み。総量値があるのは2,393件。

### ⚠️ 実装時の必須ガード

**`method` 列を必ず見ること。** 同じ食品でも分析法で **1.4〜5倍** の差が出る。

| 食品 | プロスキー | AOAC2011.25 | 倍率 |
|---|---|---|---|
| 精白米めし | 0.3g | 1.5g | 5.0倍 |
| 食パン | 2.2g | 4.2g | 1.9倍 |
| 押麦(乾) | 7.9g | 12.2g | 1.5倍 |
| 糸引き納豆 | 6.7g | 9.5g | 1.4倍 |

**→ `method` が異なる食品同士で「置き換え提案」を出してはいけない。**
実例：玄米めし(1.4g/プロスキー) と 精白米めし(1.5g/AOAC) を比べると
「玄米の方が少ない」という誤った結論になる（生では玄米3.0g vs 白米0.5gで6倍差）。

水溶性/不溶性の内訳が統一形式で揃うのは **1,286食品 / 2,538 = 51%** のみ。
→ v1では総量1本で運用する判断の根拠。

## servings.csv — 常用量テーブル（178品目）

プリセットタップとAI名寄せ辞書の両方のseed。

| 列 | 内容 |
|---|---|
| `category` | 主食 / 豆類 / 種実 / いも / 野菜 / きのこ / 海藻 / 惣菜 / 果物 / その他 / 菓子 |
| `label` | ユーザーに見せる表示名 |
| `aliases` | AI名寄せ・検索用の別名（`\|`区切り）。**ローカル辞書のキーに使う** |
| `unit_label` | 「1パック」「1杯」等。**g数ではなくこれを主入力にする** |
| `serving_g` | 常用量のグラム数（可食部） |
| `code` / `official_name` | 成分表の食品番号と正式名 |
| `fiber_per_100g` / `fiber_per_serving` | 100gあたり / **1回あたり**の食物繊維総量 |
| `soluble_ratio` | 水溶性の比率（実測の内訳から算出） |
| `soluble_per_serving` / `insoluble_per_serving` | **総量 × 比率** で算出した2軸（合計は必ず総量と一致） |
| `breakdown_source` | `prosky実測`(113) / `aoac実測`(4) / `推定(同群実測0%)`(6・海藻) / `該当なし(繊維0g)`(7) |
| `method` | 上記ガード用 |
| `tier` | `A`=3g以上(26件) / `B`=1〜3g(69件) / `C`=1g未満(12件) / `Z`=0g(7件) |

### 2軸の算出方式（重要）

内訳(水溶性/不溶性)は**g数を直接持たず、比率として保存して総量に掛ける**。

```
soluble_per_serving   = fiber_per_serving × soluble_ratio
insoluble_per_serving = fiber_per_serving − soluble_per_serving
```

**理由**：本表の総量はAOAC法を優先採用しているが、内訳は113品目がプロスキー法。
内訳のg数をそのまま合算すると**総量と一致しない**（例：もち麦2杯の献立で18.3g vs 16.4g）。
比率方式なら総量は本表値のまま（18g目標と整合）で、2軸の合計が必ず総量に一致する。

内訳の実測がある品目は **171 / 178 = 96%**。

### 品目を追加するとき

**手で行を書かない。** `scripts/expand-servings.mjs` の `ADDITIONS` に
`[カテゴリ, label, 表示名, 別名, 単位, グラム, 食品番号]` を足して実行する。

```bash
node scripts/expand-servings.mjs           # 生成される行を確認
node scripts/expand-servings.mjs --apply   # servings.csv に追記
npm run build:data                         # 検証つきでJSONを生成
```

繊維量・2軸の比率・tier は成分表（`fiber_foods.csv`）から機械的に計算される。
人が決めるのは**常用量（グラム）と名前だけ**。
食品番号は**調理形態まで含めて選ぶ**（「ゆで」と「生」で繊維量が変わる。
例: にら 生2.7g → ゆで4.3g/100g）。

### 設計意図
- **`tier=A` をプリセットの最上位に並べる**（1タップの価値が高い順）
- **`tier=Z`（肉・魚・卵・乳）も必ず入れる。** ユーザーが「サラダチキン」と入力したとき
  「見つかりません」ではなく「0.0g」と答えられないと体験が壊れる
- **常用量は成分表に無いため自前定義**（1パック=45g 等）。要レビュー・随時拡充

## swaps.csv — 置き換え提案テーブル（24組）

コーチの第1提案に使う。`purpose` 列で提案を撃ち分ける。

| purpose | 意味 | 組数 |
|---|---|---|
| `両方` | 総量も水溶性も+1g以上 | 8 |
| `水溶性` | 水溶性のみ+1g以上（総量は増えないこともある） | 2 |
| `総量` | 総量のみ+1g以上 | 8 |
| `推奨しない` | どちらも+1g未満 | 6 |

**両方に効く置き換え（最優先で提案）**

| Before → After | 総量 | 水溶性 |
|---|---|---|
| キムチ → **らっきょう** | +4.29g | **+4.41g** |
| うどん → **パスタ** | **+4.25g** | +1.39g |
| 白米ごはん → **もち麦ごはん** | +4.05g | **+3.15g** |
| 白米ごはん → そば | +3.55g | +1.45g |
| せんべい → ドライあんず | +2.82g | +1.29g |
| バナナ → アボカド | +2.82g | +1.09g |
| キャベツ千切り → ごぼう | +2.15g | +1.15g |
| うどん → 大麦めん | +1.79g | **+2.07g** |

**水溶性だけに効く（水溶性が不足している時のみ）**

## cautions.csv — 提案禁止リスト（9件）

**世間の常識と成分表の数字が食い違う食品。** コーチの提案候補から除外する。
実行してもメーターが動かないため、提案するとユーザーの信頼を失う。

| 軸 | 食品 | 世間の常識 | データ |
|---|---|---|---|
| 総量 | 玄米ごはん | 玄米は白米より繊維が多い | **めしでは 玄米1.4g < 白米1.5g** |
| 総量 | 全粒粉パン | 食パンより繊維が多い | +0.18gしか増えない |
| 水溶性 | 板こんにゃく / しらたき | こんにゃくは水溶性が豊富 | **水溶性0g・不溶性100%**（精粉は92%水溶性） |
| 水溶性 | わかめ・こんぶ等の海藻 | アルギン酸・フコイダンで水溶性主体 | **水溶0.0〜0.1g（0%）** |
| 水溶性 | オクラ / 山いも / モロヘイヤ | ネバネバは水溶性 | 20〜31%で不溶性寄り |
| 水溶性 | キウイ | 水溶性が多い | 23%で不溶性寄り |

列：`label` `code` `axis` `common_belief` `data_says` `reason` `coach_rule` ＋実測値

**海藻の内訳は推定値**（湯通し塩蔵わかめとまこんぶの実測0%を同群に適用）。
藻類58件中、内訳実測があるのは4件のみ。**将来の再検証対象。**

## targets.json — 目標値と表示ルール

| 項目 | 値 |
|---|---|
| 総量 | **18g**（食事摂取基準2025年版・成人女性18g以上） |
| 水溶性 | **6g** |
| 不溶性 | **12g** |

**なぜ9g/9gにしないか**：理想比は1:2、日本人の実際は1:4（厚労省）、
本テーブルの中央値は0.22。半々にすると現実的な食事で到達不可能になり、
水溶性の軸が永久に未達＝キャラが永久にくすむ。ポジティブ設計が崩れる。

キャラの5段階（**直近7日の総量平均**で駆動）と表示ルール（小数点を出さない、
「水溶性/不溶性」という語をUIに出さず「菌のごはん/おそうじ」と呼ぶ）も同ファイルに定義。
